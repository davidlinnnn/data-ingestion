# R1 source-group contract v1 — registered before prototype controls

One hypothesis: explicit multi-owner output responsibility can use public Core insertion/deletion and retained source bindings, while immutable page context is independent of the original picture crop identity. Zero model/API calls, downloads, SDK changes and holdout reads. The 8-hour ceiling includes reads, implementation, controls and reporting; the initial registration is not reset.

## Producer inputs and grouping

Only retained baseline JSON, source PDF identity, original full-page pixels, native image crops and their geometric transforms enter the producer. Evaluator groups/answers/bboxes do not enter requests or routing. Source names identify inputs, never select a policy.

A groups are connected components of physical pages sharing a native text provenance item. Every leaf text owner is a candidate, including ordinary prose, empty formula, captions and picture children. This is conservative coverage, not a character/confidence detector. Each owner has an explicit `keep` or one consuming action; new formula/code occurrences not emitted by the baseline can be added from pixel evidence without inventing native text refs. B-owned table contents remain B work.

C groups share the physical page context of native pictures (join pages only when a picture itself has multi-page provenance). All pictures retain required OCR, description and chart assessment regardless of classification. Their original image keys/crop hashes are unchanged. A separately versioned context key binds source revision, page-image hashes and page dimensions. Different pixels cannot reuse an old request identity. No padding, nearest-owner or semantic continuation rule is introduced.

Raw snapshot identity and `DoclingDocument.export_to_dict()` projection identity are both explicit. Existing C image keys use the latter, as their original producer did; Core may normalize a retained out-of-bounds bbox during load. The raw snapshot remains immutable and its original geometry is retained; normalization is not silently relabeled byte-identical. Attempt03 preserves the identity-mismatch rejection and partial producer output before this generic correction.

## Output responsibilities

- A replacement can consume multiple explicit leaf text owners across parents. Its blocks declare original source refs/pages and an existing visible before/after anchor. Public Core creates the replacement nodes, then deletes only consumed nodes. All non-target content, relative order, table data, pictures and caption edges are checked. One owner cannot be consumed twice; kept owners cannot be consumed.
- A caption replacement stays at its original caption edge with public InlineGroup/FormulaItem/CodeItem children. A public MarkdownDocSerializer extension serializes explicitly reconstructed captions through the existing typed item serializers, avoiding stock caption post-processing's second escape; untouched captions use stock behavior. This is an adapter requirement recorded with the result and reapplied after reload, not a text repair or SDK patch. New source reconstruction inside a picture is explicit formula/code sibling content, linked to that picture and page context. It is not generated description.
- Derived provenance is honestly page-envelope precision for reconstructed content; original native bbox/charspan remains in the immutable binding. No fabricated glyph/cell geometry. Source text/identity is never inferred from array index stability after Core remapping.
- C has distinct crop-only literal OCR and optional **source-group/context OCR**. Outside-crop text cannot be labeled crop-only OCR. Generated description/chart observations may cite context but never replace source captions or enter the primary Markdown. All observations remain same-revision, image-key and context-key bound. This is a new output contract, not merely putting a larger image into the old request.
- Unknown/missing/duplicate owner, stale revision/context, missing fragment/page, unsupported output or unreachable reconstruction rejects the whole group. A complete transport response does not establish semantic correctness or discovery recall.

## Controls and decision

First test generic cross-parent code and mixed picture/title reconstruction with ordinary negative context. Then replay the actual two retained counterexamples using MOCK responses; those are transport evidence only. Producer uses no source answers. Evaluate all retained 44 A source groups, 27 ordinary negatives, 41 legacy units and C's 55-page/29-picture inventory; table responsibility and incomplete source annotations remain explicit.

Check JSON reload, actual Markdown rendering through the declared serializer, image/caption preservation, same-revision supplements, directory relocation and missing dependency rejection. Positive/negative controls exercise source consumption, read-only context, code literals, math structure, reference remapping, full-page binding and budget bounds. Preserve source and method hashes before and after checks. Attempt01 retains the initial stock-caption failure and method/contract snapshot; this public extension is the same source-group hypothesis within the original R1 budget.

`METHOD_REGISTERABLE` requires an executable general input/output method, honest source precision, complete required scope accountability and computable jobs/input/output budgets. It does not mean model quality passed or inference is authorized. If legal content cannot pass without case rules/semantic repair, return `METHOD_STOP`; if the registered ceiling arrives first, return `BUDGET_STOP`. No automatic second method or extra 8 hours. OCR/reading-order and B failures are not repaired or waived by R1.
