# G2 inline temporary GPT-6 Luna API source audit

2026-10-15。**本輪採用使用者指定的 `gpt-6-luna`／`https://api.openai.com/v1/chat/completions`，重用22張既有PNG，透過direct HTTP傳回ordered JSON segments。Paragraph及page兩路均是API component比較；本輪不宣稱跑過官方API `VlmPipeline`。** 公司Qwen3仍是另外的地端候選，不由本輪API品質／latency代證。這份source audit與離線verification未存取key或呼叫API；下面執行事實來自root另行保存的request／response。

先依OpenAI Docs skill搜尋exact model／Chat Completions／images／Structured Outputs，再實際開啟[模型頁](https://developers.openai.com/api/docs/models/gpt-6-luna)、[Chat reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[vision guide](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)、[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)及[GPT-6 guide](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-luna)，才讀本機Docling exact source。模型頁列出image input、Chat Completions與Structured Outputs，支援`low` reasoning；官方頁並不證明目前帳戶access或本次可用性，也不提供此alias的固定日期snapshot。應保留response實際model identity，不能自行換模型。

選定request設定是`model=gpt-6-luna`、`reasoning_effort=low`、`store=false`，省略`stream`（預設nonstreaming），**省略temperature／top_p／logprobs／top_logprobs**，不加tools。[GPT-6 guide](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-luna)明確指出non-`none` reasoning不能帶這些sampling/logprob參數。只保留同一套low設定，不另加`none` Cartesian比較。

最小實作重用前輪direct HTTP runner (`docs/research/pdf-core-g2-api-2026-10-14/run.py`)的safe client、sequential one-attempt、raw-response保存與finish檢查，換成本輪已凍結17個producerparagraph與5個wholepage PNG清單，以及新segment prompt／schema。PNG以原bytes放進Chat的`image_url.url=data:image/png;base64,...`，顯式`detail=high`；這兩個巢狀欄位由[Chat vision guide](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)示範。保留PNG SHA／尺寸與外部source mapping；該guide的model sizing table沒有列出GPT-6 Luna的精確patch／resize規則，因此不保證service保持原像素或能精準定位。不要套用其他模型的image limit。

`response_format`使用`type=json_schema`、命名且`strict=true`的schema；root object為object，各層object都`additionalProperties=false`，所有properties列required，需要不確定／未辨識值時明示nullable。將paragraph／page items內的text、math、code segments依原文順序排列；保留普通文字、數學表示、code換行／縮排與uncertainty。Schema與prompt不含oracle答案、targetLaTeX或逐案正確內容。嚴格schema只約束shape，不能保證轉錄、數學、typing、相對位置或來源正確；拒答與截斷仍須處理。[Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)

這是與Granite default DocTags prompt**不同的method**：samePNG可固定視覺輸入，不能把schema／prompt／reasoning／service image處理的差異說成單一model因果排名。JSON能直接承載ordered span types並保留不確定性，便於本輪fail-closed paragraph adapter；但必須在本地驗證後明確組裝Docling items／inline group，不能把JSON字串交給DocTags parser當成已整合。DocTags則可由既有官方page assembly直接解析，但generic API模型沒有DocTags訓練或語法正確的官方保證；若改用DocTags，必須另凍結grammar prompt與output format，而非在本次JSON結果上靜默轉成另一個試驗。

已讀Docling2.102.0／Core2.96.0的exact source hashes (`source-audit.json`)，integration seam如下：

- `ApiVlmEngineOptions`支援`engine_type=API_OPENAI`、完整Chat endpoint、runtime headers、params、timeout及concurrency。新runtime的`VlmConvertOptions`可指定custom `VlmModelSpec`（明確model ID／prompt／response format），並交給`PdfFormatOption(pipeline_cls=VlmPipeline)`，須`enable_remote_services=True`。沿用local page比較的images_scale1／stage.scale2、force_backend_textFalse、batch1，才是最小官方page seam；**本輪不執行這條路**。
- API engine (`docs/prototypes/pdf-checkpoint-prototype/.venv/lib/python3.12/site-packages/docling/models/inference_engines/vlm/api_openai_compatible_engine.py:125`)總會加入`temperature=input_data.temperature`（page stage為0），再套`options.params`。顯式`max_completion_tokens`會刪除預設`max_tokens`，但params無法讓temperature key真正消失。保持官方engine原樣時，與GPT-6 Luna相容的sampling方向是`reasoning_effort=none`，這會改變本輪選定low設定，所以不採用；也不把`temperature:null`冒稱已省略或已驗證可用。若未來要保留low而走pipeline，需要具名、可審閱的transport adapter移除該key並重新驗證，不能只換preset便宣稱相容。
- API request helper (`docs/prototypes/pdf-checkpoint-prototype/.venv/lib/python3.12/site-packages/docling/utils/api_image_request.py:72`)會把影像重編成RGBA PNG、message僅帶image與prompt、未帶image.detail，並對content做`.strip()`。它只回text／total_tokens／mapped stop reason，丟失完整provider response；`content_filter`／`length`有專門映射，其他finish reason都映成END_OF_SEQUENCE，catch-all exception則回空text／0／UNSPECIFIED。這些是後續真正integration需要觀察的行為，不能把空輸出或pipeline status直接當品質結果。
- `VlmConvertModel.__call__`硬編`max_new_tokens=4096`；API params的`max_completion_tokens`可覆蓋transport實際cap。`VlmPipeline`依model response format組裝，無任意JSON segment parser。DocTags parser的isolatedpage編號／image-pixel座標與crosspage paragraph seam仍須外部mapping／assembly驗證，API模型不會自動改正。

本輪direct component保留raw HTTP status/body、request ID、requested／returned model、client round-trip、prompt/schema/settings／image hashes及usage。`max_completion_tokens`是**visible output＋reasoning tokens**合計上限，不能和Granite的1024／4096 generated-token cap視為等值；actual cap須在run前逐job凍結，reasoning_tokens若provider回傳則保留。[Chat reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。Chat response沒有本機Granite generate hook的raw token IDs／EOS trace，應明示unavailable，不能捏造相同可觀測性。

先保存原response，再檢查HTTP成功、預期choices/message shape、`finish_reason=stop`、無refusal、非空content、嚴格JSON parsing、schema與本地segment／source invariants。`length`／content filtering／refusal／transport或parse失敗保留為相應執行／交付缺口，不能把半份結果作已完成的普通品質失敗。[finish/refusal處理](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。實際沿用HTTPClient timeout180／connect20、follow_redirects=False、trust_env=False、22次sequential sharedlock、每job單次attempt；沒有另外的hard180秒wall deadline或6GiB RSS／8GiB available-memory observer。RTT是本機client觀察，沒有remote RAM／GPU、server取消或CPU模型資源guard的證據。`store=false`是completion storage選項，沒有推導為零provider retention。
