The reviewer will keep these boundaries separate:

1. **Saved inputs and automatic selection.** Verify request images byte-for-byte against the snapshot, original physical source pages, whole provider refs/character spans and all fragments in provider order. A full-page route and a producer-crop route are distinct methods/context; differences in prompt, resolution, token budget or output schema must remain visible. A hosted replacement is not an official Docling VLM pipeline unless the exact official pipeline was actually used.
2. **Raw response and completion.** Retain raw response JSON/text, exact prompt/configuration, requested versus returned model, timestamps, usage, finish/incomplete/refusal/error metadata, and unsuccessful attempts. No source answers, selected expected tokens or case-specific repairs may enter a producer request. Distinguish API/model omissions from parsing, cleanup, escaping or serializer losses. Preserve raw text even when the proposed parse is rejected.
3. **Prose and inline semantics.** Compare complete paragraphs and source math/code in reading order. Equivalent LaTeX macros may change spelling but not inequalities, equality boundaries, sign, exponent/subscript, prime, arrow direction, argument order or identifier characters. Count all repeated occurrences, not only distinct strings. Present any ordinary prose typo/punctuation deviation explicitly. The user's previous `OpenAI→OpenAl` judgment applies only to that minor prose occurrence; it does not relax source identifiers or math/code requirements.
4. **Reinsertion.** Reconstruct the complete before/after Markdown and permit only declared complete-item substitutions once, in native item order. Preserve native JSON bytes, original item refs, orig/text, graph, provenance and neighbor objects. Do not silently choose the first root block to hide duplicates, absorb a next paragraph, apply hidden picture-child replacements without an explicit adapter, or count a proposed output as applied. Preserve and explain abstentions. Structural application is not semantic acceptance.
5. **Geometry and cross-page identity.** Original parser/crop coordinates remain raw. Independently verify transforms to physical PDF-point coordinates in sidecars, including both E13 fragments and the 24-pixel stitched gap. Producer paragraph boxes and inferred output spans are not measured glyph boxes. Correct geometric overlap alone does not prove semantic fragment alignment; the earlier SEAL output placed p4 text in a p3-only box. No new IoU/CER threshold or source-measured token precision is inferred.
6. **Regression and negative controls.** Check WikiSkill362's entire opening `Statistical significance testing We perform paired bootstrap significance tests with 1,000 iterations` survives; the earlier adapter accepted its loss. Retain tests against wrong threshold, arrow/prime/subscript, identifier change, duplicated cross-page fragment, dropped source prose, changed code nesting, missing physical fragment, stale hash, partial replacement, duplicate item, reordered native items and outside-scope Markdown changes. Controls mutate only in-memory evaluator data and do not run API inference or edit outputs.

A small reviewer checker will bind these source rules to the actual saved output schema after it arrives. It will reuse the prior declared mathematical spelling equivalences, while checking the clean frozen reference passes before using a mutation as a negative control. Source-aware manual prose comparison is evaluator-only. No overall quality percentage, all-document qualification or pure single-variable causal claim will be inferred from this bounded set.
