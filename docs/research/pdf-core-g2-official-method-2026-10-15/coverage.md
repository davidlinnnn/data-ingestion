## 最小組合建議

保留 **Standard／Heron＋TableFormer V1 accurate＋明確模型的 selective RapidOCR** 作比較基底，開啟必要來源影像並保存首次完整 provider／診斷。偏好啟用的小 classifier 有合理的 CPU 有界證據。CodeFormulaV2 僅保留已驗 code 任務；公式結果不能由 code 成功代證。新版 heading recovery 與頁面方向模型均可保留候選，但前者要相容 stack，後者的來源座標 adapter 是本案整合。

困難公式／inline、複雜表格、圖意／chart 與繁中圖片 OCR 仍需經驗證的模型／方法。優先檢查官方 remote `VlmPipeline` 能否減少自訂 planner／typed parser／回填成本；不預設整頁會勝出，也不因 API 能回應就採用。既有 custom context candidate1 已不選作完整 challenger，程式與原始評分凍結作參照。

這是下一個可行性比較的最小組合，**不是已可交付的全功能 Processing Profile**。目前也沒有可辨別所有來源語義錯誤的可靠 runtime routing gate；不能把「Standard＋僅在判斷有錯時 fallback」直接說成完整方案。

## 原需求與實驗契約的差異

- F13 明確要求必要行內公式的 LaTeX；只留普通文字的數學意思不足。
- F14 要內容、符號、區塊、註解與縮排忠實；沒有自動新增「每個 inline code token 都必須 typed JSON」要求。DGM648 缺 typed `edit` 與 DGM650 block/segment 不合可造成實驗 parser 失敗，應另列表示／接點；DGM646 `{}`→`[]` 則是內容級錯誤。所有歷史評分與 raw outputs 保留。
- 最近 36 項的 25 pass／5 minor／6 material 是兩個原 rubric 的分類，不是統一產品 accuracy；34 項可回填也不是 Acceptance。原 selected scope 是41來源單位，五項未執行不得刪除。
- SEAL30 新增 standalone `SE` 的 math 型別註記與舊 E13 的11處判準不同，不能當既有 F13 正例退化。
- 裁圖內容已完整時仍讀錯 prime、數值、code 字面值或識別字，應比較方法／模型或記錄缺口，不靠逐案字串修補。

## 已驗與只查到官方能力的界線

實際模型身份／revision 見 JSON registry 與各原報告 method metadata。`Granite-Docling-258M` 確曾跑真正本機官方 `VlmPipeline`；所有 `gpt-6-luna` 歷史結果則是 direct HTTP component，**尚未驗真正官方 remote VlmPipeline**。Granite Vision 4.1-4B 只保留歷史 table CPU 有界逾時；本輪 F11／F12 未跑其推論。公司 Qwen3-VL 只知道 family、尚無 exact model ID／GPU 執行證據；不是唯一候選。PaddleOCR-VL 只有使用者引用官方轉換例，不列已驗。其他 OCR/layout/VLM 候選並未全部窮舉。

## 收斂次序與真正需要使用者的點

1. Agent 可先完成官方 API／parser／provenance 預檢；適用才作固定來源的最小方法比較，不適用就記錄 no-go，不疊接複雜修補。
2. 依固定41來源工作、既有正例與必要任務檢查忠實交付、coverage／缺失／失敗及成本；不放寬原需求或新增調參搜尋。先選可行方法，再鎖一個 challenger，獨立來源標註後才執行一次 paired holdout。最多三組配置規則保持。
3. 需要到公司實測時，使用者才需補 exact model ID／revision、API/serving 能力、GPU 型號／張數／VRAM／可用容量。這是部署事實，不是要求先替 agent 選模型；Qwen3 或其他可行地端候選由同任務證據比較。
