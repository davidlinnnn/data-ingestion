## Recommended bounded comparison

Use **the official Granite preset in the existing code/formula stage for the SEAL Eq. 2 crop**, then use its **full-page conversion prompt for the English scan and SkillOpt p. 8**. These are distinct tasks with distinct outputs. Keep the same frozen G1 sources, input crops, expected values, and acceptance rules. A crop result establishes recognition only; it does not establish formula detection, inline discovery, source association, or Canonical backfill.

The pinned [IBM model card](https://huggingface.co/ibm-granite/granite-docling-258M/blob/982fe3b40f2fa73c365bdb1bcacf6c81b7184bfe/README.md) identifies a document conversion model with full-page and region inference, equation/code/table instructions, and experimental Chinese support. It is not a general image description model. Use the model-specific instructions below rather than the generic Hugging Face autogenerated candy/photo examples.

| Probe | Input and instruction | Output and initial cap | What it can establish |
| --- | --- | --- | --- |
| SEAL p. 4 Eq. 2 | Same frozen equation crop/resampling as round 2; `<formula>` | LaTeX; 512 new tokens | Whether this recognizer preserves both piecewise branches and avoids treating the footnote marker as an exponent |
| English scan p. 1 | Whole physical page, scale 2; `Convert this page to docling.` | DocTags; 4096 new tokens | Text completeness **and** model-generated order, without manually sorting the result |
| SkillOpt p. 8 | Whole physical page, scale 2; same conversion instruction | DocTags; 4096 new tokens | Table 2 panel/header/condition/value binding in its full-page context, with official parsing |

These caps are **exploratory budgets**, not accepted production limits. 512 is ample for the short reference equation, but still inspect EOS; a capped result cannot establish a completed wrong answer. Whole-page output can need thousands of tokens. If either full-page probe reaches 4096, record **truncated/unresolved**, not a quality failure. The model card demonstrates 8192; the installed full-page stage requests 4096. Do not repeatedly retry longer decoding merely to fill a grid. A 180-second / 6-GiB sampled tree-RSS stop is a local feasibility outcome under this guard, not a proof that another CPU/GPU deployment cannot work.

## Concrete installed APIs

The [official preset example](https://docling-project.github.io/docling/_generated/examples/minimal_vlm_pipeline/) shows `VlmConvertOptions.from_preset(...)` and explicit engine overrides. For this project, **do not copy its Apple MLX branch**. The following imports/preset construction were checked locally without loading weights:

```python
from docling.datamodel.accelerator_options import AcceleratorOptions
from docling.datamodel.pipeline_options import CodeFormulaVlmOptions, VlmConvertOptions
from docling.datamodel.vlm_engine_options import TransformersVlmEngineOptions
from docling.models.inference_engines.vlm import VlmEngineInput, create_vlm_engine

engine_options = TransformersVlmEngineOptions(
    device="cpu", torch_dtype="float32", compile_model=False,
    quantized=False, trust_remote_code=False,
)
formula_options = CodeFormulaVlmOptions.from_preset(
    "granite_docling", engine_options=engine_options,
)
page_options = VlmConvertOptions.from_preset(
    "granite_docling", engine_options=engine_options,
)
revision = "982fe3b40f2fa73c365bdb1bcacf6c81b7184bfe"
formula_options.model_spec.revision = revision
page_options.model_spec.revision = revision
```

For the formula A/B, reuse [round-2 probe.py](../../pdf-core-g2-round2-2026-10-14/models/probe.py): construct `CodeFormulaVlmModel` with `formula_options`, use `stage._get_prompt("formula")`, call `stage.engine.predict_batch(...)`, and save raw output before `stage._post_process(...)`. The official stage implements `<formula>` and `<code>` prompts for **both** CodeFormulaV2 and Granite presets. It only selects existing `FORMULA` text items and code items; changing the preset does not add an inline detector.

For page probes the minimum engine call is:

```python
# artifacts / "ibm-granite--granite-docling-258M" points at the pinned snapshot.
# Construction eagerly loads the model: start the load timer BEFORE this call.
engine = create_vlm_engine(
    options=page_options.engine_options,
    model_spec=page_options.model_spec,
    enable_remote_services=False,
    artifacts_path=artifacts,
    accelerator_options=AcceleratorOptions(device="cpu", num_threads=4),
)
output = engine.predict_batch([
    VlmEngineInput(
        image=page_image,
        prompt=page_options.model_spec.prompt,
        temperature=0,
        max_new_tokens=4096,
        extra_generation_config={"skip_special_tokens": False},
    ),
])[0]
```

This is the official engine/prompt/parser **component probe**. It is not an end-to-end `VlmPipeline` conversion. The exact pipeline entry point, when needed, is `PdfFormatOption(pipeline_cls=VlmPipeline, pipeline_options=VlmPipelineOptions(vlm_options=page_options, accelerator_options=AcceleratorOptions(device="cpu", num_threads=4)))` supplied to `DocumentConverter(format_options={InputFormat.PDF: ...})`; `converter.convert(pdf, page_range=(8, 8))` selects physical p. 8. Keep `page_options.force_backend_text=False` for model OCR/order comparison.

## Parsing and provenance checks

Use the public Core parser, as demonstrated by the model card and implemented in [Core 2.96.0 document.py](https://github.com/docling-project/docling-core/blob/v2.96.0/docling_core/types/doc/document.py):

```python
from docling_core.types.doc import DoclingDocument
from docling_core.types.doc.document import DocTagsDocument

doctags_doc = DocTagsDocument.from_doctags_and_image_pairs(
    [output.text], [page_image],
)
document = DoclingDocument.load_from_doctags(
    doctags_doc, document_name="G2 probe",
)
document.save_as_json(output_dir / "document.json")
document.save_as_markdown(output_dir / "document.md")
```

Save the untouched DocTags, generation token IDs/EOS/cap evidence, raw engine metadata, input PNG/hash, render scale, PDF hash, physical page, actual parameter devices/dtypes, and method configuration. Parse and export only after saving raw output. Inspect both raw and structured output; a parser can discard malformed text or recover an unclosed tag as an **empty** item. Successful export is not source fidelity or complete-output proof.

Core parses `<loc_...>` coordinates normalized by 500, then scales them to the supplied image width/height. A single-page parser starts at page 1 and has image-pixel page dimensions. A physical PDF p. 8, crop offsets, and PDF-point coordinates therefore require a separately recorded mapping; do not publish image-pixel boxes as source PDF points. The direct crop recognizer still needs the external frozen source locator.

Meaningful source checks remain unchanged: the scan's two paragraphs must be complete and consecutive before the right-column content; SkillOpt must preserve all six panels and the eight critical comparisons with valid condition/header links, not just contain 84 numbers; formula must preserve both cases and distinguish its footnote marker. Do not infer a full 84-point table error rate from checking only critical cases.

## Installed-code traps to preserve in the run record

The following facts come from the installed source files, not from assumptions about the current online default. The local package root is `docs/prototypes/pdf-checkpoint-prototype/.venv/lib/python3.12/site-packages/`:

| File under package root | Verified behavior / implication |
| --- | --- |
| `docling/datamodel/stage_model_specs.py` | `CODE_FORMULA_GRANITE_DOCLING` and `VLM_CONVERT_GRANITE_DOCLING` share the pinned repo family, but use PLAINTEXT vs DOCTAGS. Model spec carries 8192; it does not force an individual call's token cap. |
| `docling/models/stages/code_formula/code_formula_vlm_model.py` | Stage prompt is `<formula>`/`<code>`, default call cap 2048, image scale 1.67 and expansion 0.18; fixed oracle crop bypasses detector/crop expansion. `_post_process` removes specific end/location tokens, not semantic errors. |
| `docling/models/stages/vlm_convert/vlm_convert_model.py` | `__call__` resizes `page.image` by options.scale (preset 2), then optional max_size; calls with 4096 and no explicit decoder flags or stop strings. `process_images` does not apply that resize. Avoid accidentally scaling an already-rendered 2x image by another 2x. |
| `docling/models/inference_engines/vlm/factory.py` | `create_vlm_engine` forwards explicit engine options and model configuration; Transformers constructor eagerly initializes. A later `initialize()` timer is only a no-op check. |
| `docling/models/inference_engines/vlm/transformers_engine.py` | Actual Transformers options override dtype; explicit CPU uses SDPA. `predict_batch` takes token cap, stop strings, and decoder flags from `VlmEngineInput`; do not assume the preset's extra generation settings propagate. It returns stop reason `unspecified`; metadata num_tokens includes input. Preserve the generate hook to distinguish output tokens/EOS/length. |
| `docling/models/inference_engines/vlm/_utils.py` | `artifacts_path` is a parent containing repo-name-with-slash-replaced-by-`--`, not the snapshot directory itself. Keep the separate candidate cache. |
| `docling/pipeline/vlm_pipeline.py` | New runtime path uses one full-page `VlmConvertModel`; no separate Heron, RapidOCR, or TableFormer stage. `force_backend_text` replaces VLM text and would change this comparison. |
| `docling_core/types/doc/document.py` and `doctags.py` | Official DocTags assembly supports text/formula/inline groups/tables/figures and preserves generated item order. Parsing is not an independent layout correction or quality validator. |

The direct engine input explicitly retains special tokens so DocTags can be parsed. Record this decoder setting as part of the candidate identity; it is deliberate rather than a silent assumption about the stage default. Do not copy generic `device_map="auto"`, BF16, flash attention, quantization, or `--revision untied` serving examples into this CPU/pinned candidate.

## Region alternatives and their limits

The official model instructions include formula/code recognition, table OTSL conversion, and bbox-guided OCR. Thus a full-page image plus normalized bbox prompt is supported by the **model**, but is not automatically a configurable table replacement in `StandardPdfPipeline`. The current `VlmConvertOptions` stage offers scale/max_size/full-page prompt, not a source-locator-aware per-region adapter. A later region candidate must record the bbox producer, keep the full logical table and caption/conditions, and own its source coordinate/backfill seam. It must not collapse six-panel Table 2 into unrelated easy crops and call the complete table passed.

The dedicated Granite Vision table-structure model discussed in the plan is a different model/stage from Granite-Docling-258M. Neither this note nor an execution success establishes their equivalence, company Qwen3 behavior, GPU latency, or high-frequency throughput.
