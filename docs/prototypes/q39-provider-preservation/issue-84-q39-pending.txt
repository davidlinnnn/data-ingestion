## 要完成的決定

定義第一個 pilot run 使用的 **PDF Processing Profile 與交付給 Canonical 的結果契約**：包含哪些功能、每項輸出什麼、哪些情況算完成、哪些缺漏阻止 Canonical Acceptance，以及如何驗證。此處的 final 指本次第一版決定，不承諾一次定義未來所有格式或所有 Docling 功能。

建議先決定可消費的輸出與用途，再選模型、版本和執行方式。官方具備功能、profile 啟用、adapter 完整保留、pilot 通過品質驗證，是四件不同的事。DoclingDocument 是處理器結果；Canonical Knowledge 仍由 #32 的表示、證據與 acceptance 契約約束。

## B. 同樣讀過，但須另作處理方法／運行範圍決定

以下不是額外的文件語意輸出。選了 F01–F22，也不代表必須同時採用這些工具。

| 範疇 | 官方 Usage 涵蓋內容 | 對本次決定的意義 |
|---|---|---|
| PDF pipeline | Standard pipeline；NativePdfPipeline；整頁 VLM conversion | 官方 NativePdfPipeline 只用原生 cell／bitmap，沒有 layout／OCR／table models；它與本 repo 名為 selected-native-v1、實際使用 layout＋TableFormer 的方法不同。VLM 是替代方法，不是免費疊加的 enrichment。[Advanced][advanced]、[Vision][vision] |
| Models／engines／硬體 | layout、OCR、TableFormer／其他 table method、classifier、code/formula、description、VLM；CPU／CUDA／MPS／XPU、Transformers／MLX／API／vLLM 等組合 | 按選定輸出挑一個可交付方法；不同 preset 的 DocTags／Markdown／region 支援不等價。型錄有 WIP，不能當已可用。[catalog][catalog]、[GPU][gpu] |

| MCP／Agent skills／Jobkit | Agent tool access／工作流程指引；job 執行與來源／輸出 connector | 屬於整合工具；不把它們算成新增 PDF feature，也不因讀到 Jobkit 就替換既有 Temporal。[MCP][mcp]、[Skills][skills]、[Jobkit][jobkit] |

## C. 與先前結論相比，這次補齊／重開什麼

1. **把 Usage 的閱讀範圍變成逐頁可核對清單**，不再只用一組 enrichment 名稱代表完整廣度。補清 NativePdfPipeline、JSON reimport 的 image refs、progress 語意、Agent skills／Jobkit／managed service，以及 audio/video 範圍。
2. **避免錯誤合併能力**：page OCR ≠ picture OCR；caption ≠ generated description；heading detection ≠ hierarchy；table extraction ≠ table-dependent analysis；native code/formula observation ≠ VLM reconstruction；schema extraction ≠ 保留 form fields。
3. **新增文件發現不都等於新 release 功能**。本次不宣稱這些能力都是 #70 以後新增；#70 已涵蓋多數 PDF 核心能力。moving docs、tagged source 和實際測試各自標示。
4. **重開功能選擇**：#70 的 retain／defer 建議與 #72 的 restricted-use 結論不作為這次自動排除條件。F05/F11/F12/F13/F14 若被選成必含，要明確改寫 #72 與 #80–#83 的相關範圍；F03 亦需新增 hierarchy 的輸出／驗證約定。
5. **保留歷史品質證據**：既有表格／公式／圖像失敗案例仍是新方法需面對的 regression cases；沒有因官方存在某功能就推翻實測限制。沒有重跑新模型、遠端 endpoint 或完整 pilot。
