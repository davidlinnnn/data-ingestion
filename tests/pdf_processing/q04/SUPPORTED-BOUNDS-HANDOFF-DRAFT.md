# Draft Q04 measured-bounds handoff to T09a #44

This is a draft for mainline review, not a production sizing guarantee or a published #44 update. Q04's integrated current-v3 producer passed the six fixed fixtures' fresh/restored/exact replay and full typed-graph oracles (AI/AJ), the fixed Wiki→YOLO→AIMA→native→Wiki warm sequence and request-20 recycle (AH), required relationship interruption/recovery/replay (AS), active telemetry-loss fail-closed (AU), and native owned **worker-process** drain/recovery (BE). Each pass applies to its exact frozen source, producer, profile, method, image and policy; see `CURRENT-ACCEPTANCE-MATRIX.md` for identity-specific rows. These runs use actual Temporal Activities and shared versioned object storage.

The BE process-recovery trial used one serial native 51-page request, seven OCR components, one worker Pod on `internal-a2a-vs6-local-worker2`, a 5 GiB container hard limit, 4 GiB all-sample cgroup guard, 250 ms process/cgroup sampling with a one-second allowed gap, zero OOM and zero worker-Pod full-PSI avg10. Outer admission required at least 4,831,838,208 bytes available for 60 seconds; runtime floor was 1,610,612,736 bytes; the same 32 historical Deployments remained off. BE's 834 samples were complete, with 0.558-second maximum gap, maximum worker-Pod cgroup memory 2,153,619,456 bytes and minimum node MemAvailable 4,980,805,632 bytes. These are measured outcomes for this fixed arrangement, not safe ceilings for other fixtures, concurrency or unpaused services.

The colocated object service was the material limit. At 512 MiB during AY, exact MinIO cgroup limit events/full PSI coincided with a node PSI stop; no OOM occurred. A temporary 768 MiB limit allowed BA–BE to reach native business completion without that outer stop, but BE still peaked at 805,036,032 of 805,306,368 bytes and recorded eight new `memory.events max` events and 16.095 ms full PSI. It was restored to 512 MiB after BE with UID/old-limit preconditions; the replacement object Pod is Ready, Temporal idle and storage health HTTP 200. Neither 512 nor 768 MiB is supported as a generally safe object-service bound. Do not infer a false PSI guard, a required cluster replacement or a need to tune parser concurrency from these data.

Unqualified conditions for #44: in-flight Kubernetes **Pod loss/replacement** on this producer; MinIO's sustainable bound and behavior with the 32 historical Deployments restored; concurrency/group-size changes (#45); longer or different documents, whole-book, scan-first/unreliable-native-layer and universal language/PPT support. The next Q04 Pod-loss design must split the coordinator from the replaceable Activity Pod, preserve exact UID/cgroup/process attribution and fail closed under unchanged guards; see `POD-LOSS-NEXT-WINDOW.md`. #44 remains responsible for final operating-scope acceptance.
