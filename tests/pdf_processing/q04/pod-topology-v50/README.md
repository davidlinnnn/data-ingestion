# Q04 AY worker-process drain with object-service telemetry

AY uses a fresh identity for one native worker-process drain/recovery window. It keeps AX's frozen AH producer, reviewed exact current-v3 oracle, resource thresholds, deadlines, cleanup and fail-stop behavior. It adds only read-only, 250 ms sampling of the exact existing `objects` container cgroup (memory.current, memory.stat, memory.events and PSI) to the host observer, fenced to the existing object Pod UID. The observer stops with the owned window.

AX's process recovery reached the exact 51-page native output, but the outer node PSI guard stopped terminal qualification during a pressure burst attributed to the colocated object service. Sequential read-only replay of all 271 AX objects did not reproduce the burst. AY is one controlled execution with no automatic retry. A pass may prove process recovery; it does not prove Pod drain/recovery or close #51.
