# AZ: pre-inference provenance-path failure

AZ was the first attempt to test the same Q04 process-drain workload with the existing object-service container limit temporarily raised from 512 to 768 MiB. It stopped at the pre-inference gates: `python_executable`, `packages_imports` and `models` all failed because the generated runner referred to nonexistent `candidate/yolo-reviewed-b-fail/RETAINED-REPLAZ.json` instead of the frozen `RETAINED-REPLAY.json`. This is an acceptance-runner path substitution defect. The gate correctly failed closed: `inference_started=false`, `workflow_started=false`, and `object_written=false`. AZ gives no evidence for or against the 768 MiB memory-limit hypothesis, and no process-recovery row is promoted.

The exact 768 MiB `objects` Pod was Ready before AZ. Its read-only observer completed 504 samples with maximum interval 0.269 seconds, then stopped and was removed. The owned AZ Pod, Deployment and ConfigMaps were deleted with UID preconditions; the evidence PVC remains Bound at UID `461492f0-8248-4887-a835-6ddfac53ce06`. Historical evidence, object prefixes and the 32 held Deployments remain intact. No workflow or automatic retry ran.

The new BA runner retains the AZ result and identity, fixes only the provenance path under a fresh run identity, and adds a local regression check that the exact preflight provenance path exists in the projected workspace. The regression check failed on the malformed path before the correction and passes afterward. Q04 guards, deadlines, producer, oracle and object-service trial setting remain unchanged.
